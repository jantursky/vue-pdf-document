---
title: Templates
description: How react-pdf's props, styles, flags and render props are written in a Vue template.
---

The primitives take the same props as their react-pdf counterparts. A few things read differently in a template.

## Attributes and flags

Attributes can be written in kebab-case; they reach the engine in camelCase, so `min-presence-ahead="40"` becomes `minPresenceAhead`. The flags `fixed`, `break`, `debug`, `wrap` and `cache` are declared as boolean props, so a bare attribute means `true`:

```vue
<View fixed>…</View>
<View :wrap="false">…</View>
<Text break>Starts on a new page</Text>
```

## Styles

`:style` takes an object or an array of objects, merged left to right with falsy entries skipped. Units, flexbox and the rest of the style rules are [react-pdf's](https://react-pdf.org/styling).

```vue
<View :style="[styles.row, isTotal && styles.bold, { marginTop: 12 }]" />
```

`StyleSheet.create()` returns its argument unchanged, typed so editors can autocomplete style keys.

## Text

Strings belong inside `<Text>`, `<Link>`, `<Note>` or `<Tspan>`. A string anywhere else is dropped with a console warning, as in react-pdf. Interpolation, `v-if` and `v-for` work inside text as usual:

```vue
<Text>Bill to {{ customer }}<Text v-if="vip"> (VIP)</Text></Text>
```

## Page numbers

react-pdf's `render` prop is called during pagination, when the page numbers are known. In a template, use the `#render` slot on `<Text>` or `<View>`:

```vue
<Text fixed :style="{ position: 'absolute', bottom: 20, left: 0, right: 0, textAlign: 'center' }">
  <template #render="{ pageNumber, totalPages }">Page {{ pageNumber }} of {{ totalPages }}</template>
</Text>
```

The `render` prop also works, and may return a string, a number or vnodes.

## Typed documents

The props argument of `usePdf`, `pdf` and the render functions, and `document-props` on `<PdfViewer>` and `<PdfDownloadLink>`, are checked against the props the document declares:

```ts
// InvoiceDocument.vue: defineProps<{ customer: string; total: number }>()

usePdf(InvoiceDocument, () => ({ customer: customer.value, total: total.value })) // ok
renderToBuffer(InvoiceDocument, { customer: 'Ada', total: '42' }) // error: total is a number
renderToBuffer(InvoiceDocument, { custmer: 'Ada', total: 42 }) // error: unknown prop
renderToBuffer(InvoiceDocument) // error: customer and total are required
```

A document without declared props, or one loaded with `defineAsyncComponent`, takes any props. `DocumentPropsOf<typeof InvoiceDocument>` gives the props type for your own helpers.

The SVG elements have their own attributes: `<Rect>` needs `width` and `height`, `<Path>` needs `d`, gradients and `<ClipPath>` need an `id`, and presentation attributes such as `stroke-linecap` only take the values react-pdf draws. By default Vue lets unknown attributes through to a component, so a misspelled optional attribute isn't an error. Turn on `checkUnknownProps` to catch those too:

```json tsconfig.json
{
  "vueCompilerOptions": { "checkUnknownProps": true }
}
```

`<Canvas :paint>` receives a typed `CanvasPainter`, so `painter.moveTo(0, 0).lineTo(w, h).stroke()` is checked as you write it.

## Limits

The document is mounted as its own Vue app, so by default it doesn't see `provide`/`inject`, plugins or global components from the page that shows it. Pass what it needs as props, or see [Sharing context](/guides/sharing-context) for `inheritContext` and `setup`. Async setup and `<Suspense>` aren't awaited; load data first, then render.
